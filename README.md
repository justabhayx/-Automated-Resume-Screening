# NEXUS AI

Automated Resume Screening & Candidate Ranking Application.

## 🚀 Project Overview
NEXUS AI is an intelligent resume screening and candidate evaluation system designed for academic demonstration and professional recruitment workflows. It ingests candidate resumes (PDF and DOCX), extracts text, analyzes skill alignment against a target Job Description using a curated skill taxonomy and TF-IDF semantic similarity, and generates explainable, transparent candidate rankings.

---

## 🛠️ Technology Stack
- **Backend**: Python 3.14+, FastAPI, Uvicorn
- **NLP & Similarity**: scikit-learn (TF-IDF vectorization & Cosine Similarity), pypdf, python-docx
- **Testing**: pytest, FastAPI TestClient
- **Frontend Dashboard**: React + Vite + Tailwind CSS (Planned for Stage 3)

## 📐 Algorithm & Scoring Formula

The candidate evaluation engine combines **Semantic Text Similarity** and **Skill Taxonomy Matching**:

1. **Text Normalization**: Resumes and Job Descriptions are normalized (lowercased, punctuation cleaned).
2. **Skill Extraction**: Words and phrases are matched against a curated multi-category skill taxonomy (Programming Languages, Frameworks, Databases, AI/ML, DevOps, and Soft Skills).
3. **Semantic Similarity (70% Weight)**: Calculated using `scikit-learn` TF-IDF Vectorizer and Cosine Similarity between the Job Description and Resume text.
4. **Skill Coverage (30% Weight)**: Calculated as the ratio of matched target skills found in the resume relative to the required job skills:
   $$\text{Skill Coverage} = \frac{|\text{Matched Skills}|}{|\text{Target Job Skills}|}$$
5. **Overall Score (0–100)**:
   $$\text{Score} = (0.70 \times \text{Text Similarity Score}) + (0.30 \times \text{Skill Coverage Score})$$
6. **Ranking**: Candidates are sorted in descending order of their overall score and assigned sequential ranks.

---

## ⚠️ Limitations & Disclaimers

- **Decision-Support Estimate**: Scores and rankings generated by NEXUS AI are decision-support estimates to assist human recruiters. They are **not** predictions of job performance and must **not** be used for fully automated hiring decisions without human review.
- **Parsing Constraints**: Scanned image-based PDFs without embedded text layers require OCR (optical character recognition), which is outside the scope of this lightweight academic build. Standard digital PDF and DOCX files are fully supported.

## 🔌 API Endpoints

### `GET /`
Returns welcome message and API metadata.

### `GET /api/health`
Returns application health status and version.
* **Response**: `{"status": "ok", "version": "0.2.0"}`

### `POST /api/screen`
Screens multiple resumes against a job description.
* **Content-Type**: `multipart/form-data`
* **Form Parameters**:
  - `job_description` (string, required): Full text of the job description.
  - `resumes` (file array, required): Multiple PDF or DOCX files (Max 5 MB each).
* **Response**: JSON object containing job summary, total submitted, successful evaluations, candidate rankings with scores, breakdown metrics, matched/missing skills, explainable feedback, and error logs.
